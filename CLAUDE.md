src/Arcanist.Extensibility/  SDK de extensiones (IArcanistExtension, manifiesto)
src/Arcanist.Web/             panel de administración: Angular 22 + Tailwind v4 + spartan-ng (paquete npm `arcanist-web`)
src/Arcanist.Tray/            app de bandeja para Windows y de la barra de menús de macOS (Avalonia 12 + Velopack), net10.0-windows y net10.0
native/arcanist-audio/        crate Rust de análisis de audio (Symphonia) y del analizador DJ de la extensión AI, con C ABI para .NET

`Arcanist.Web` **no está en la solución `.slnx`** (Angular no es un proyecto MSBuild); se construye y prueba por separado con npm.

**Crates nativas** (`native/arcanist-audio`, `native/arcanist-p2p` y `native/arcanist-player`, Rust 1.91+: la edición 2024 y lo que pide iroh):
- `dotnet build` del servidor ejecuta `cargo build --release` de las tres si hay Rust (incremental, target `BuildNative` del csproj, que recorre los ítems `NativeCrate`) y copia `arcanist_audio`/`arcanist_p2p`/`arcanist_player` (`.dll`/`lib*.so`/`lib*.dylib`) a la salida. Sin Rust ni librerías precompiladas, avisa y el servidor funciona sin análisis ni red P2P. La del reproductor es opcional (`Optional="true"`): en Linux necesita `libasound2-dev`, y si no compila solo falta el audio del servidor. `-p:SkipNativeBuild=true` (o el antiguo `SkipNativeAudioBuild`) no llama a cargo.
- Para otros RID: `packaging/native/build.sh <rid>` deja las tres librerías en `artifacts/native/<rid>/`, de donde las toma `dotnet publish -r <rid>`. Linux usa cargo-zigbuild con glibc 2.27 (`pip install cargo-zigbuild ziglang`); para el reproductor, el script baja alsa-lib de snapshot.debian.org (SHA-256 fijados) como sysroot y le pone `rpath=$ORIGIN`, así la imagen Docker lleva `libasound.so.2` junto al servidor.
- `cargo test --release --manifest-path native/<crate>/Cargo.toml` para sus tests. Los de la P2P conectan dos nodos en esta máquina sin salir a internet.
- Bindings móviles: `cargo build --release --features mobile` y `cargo run --features bindgen --bin uniffi-bindgen -- generate --library <librería> --language kotlin --language swift --out-dir <dir>` (ver `docs/developers/p2p.md`). La raíz tiene un `.gitignore` de .NET que ignora `bin/`: por eso el binario de bindgen vive en `native/arcanist-p2p/bindgen/`. Ejemplos de diagnóstico: `cargo run --release --example analyze -- <archivos>` (análisis y velocidad) y `--example compare -- <referencia> <archivos>` (similitud de huellas).
- Los pánicos se capturan en la frontera FFI: un archivo corrupto nunca tumba el servidor. **No poner `panic = "abort"`.**

**Core (.NET)**, desde la raíz:

```bash
dotnet build Arcanist.slnx
dotnet run --project src/Arcanist.Core          # http://localhost:5263 / https://localhost:7137
dotnet test                                      # todos los tests
dotnet test --project tests/Arcanist.Core.Tests -- --filter-method "*Nombre_del_test"   # un test
dotnet test --project tests/Arcanist.Core.Tests -- --filter-class "*DataDirectoryTests" # una clase
dotnet test --project tests/Arcanist.Tray.Tests  # tests del tray (solo Windows)
```

- **Si el servidor de desarrollo está corriendo**, bloquea `bin/Debug/arcanist.exe`: compilar y probar con `--artifacts-path artifacts/test-build` (dentro del repo, para que `ApiContractTests` encuentre la raíz) y crear migraciones con `--configuration Release`. No parar el servidor del usuario.
- Los tests usan **xUnit v3 sobre Microsoft Testing Platform**, activado en `global.json` (`"test": { "runner": "Microsoft.Testing.Platform" }`). Por eso no hay `Microsoft.NET.Test.Sdk` ni `xunit.runner.visualstudio`, y los filtros van después de `--` con la sintaxis de MTP, no con `--filter` de VSTest.
- `xunit.runner.json` amplía a 30 s la espera de xUnit al cerrar el proceso de tests (por defecto 10 s). Con la máquina muy cargada, el cierre normal superaba los 10 s y xUnit fallaba con "Foreground threads were left running" aunque todos los tests pasaran; se investigó y no había hilos de Arcanist vivos. Una fuga real sigue fallando, porque nunca termina.
- Los tests de integración usan `ArcanistFactory` (`WebApplicationFactory<Program>`), que arranca el servidor con un directorio de datos temporal y el entorno `Testing`.
- `ArcanistFactory` desactiva el análisis en segundo plano (`Arcanist:Analysis:Enabled=false`); los tests que lo necesitan lo activan y esperan con `WaitForAnalysisAsync()`. Su tercer parámetro permite reemplazar servicios (por ejemplo, `FakeOnlineServices` para los clientes HTTP de los servicios en línea: los tests nunca salen a internet).
- Los tests que necesitan un ffmpeg real (`TestFfmpeg.Require()`) se marcan como **skipped** si no hay ffmpeg en el `PATH`.
- `DatabaseProviderTests` ejecuta las mismas aserciones contra SQLite en memoria y contra PostgreSQL 17 en un contenedor de Testcontainers. Si Docker no está disponible, los de PostgreSQL aparecen como **skipped**, no como verdes. Incluye un test que falla si el modelo cambió sin migración para alguno de los dos proveedores.

**Migraciones EF Core** (herramienta local `dotnet-ef` en `dotnet-tools.json`; ejecutar `dotnet tool restore` una vez). Cada cambio de modelo necesita **las dos**:

```bash
dotnet ef migrations add <Nombre> --project src/Arcanist.Core --context SqliteArcanistDbContext --output-dir Data/Migrations/Sqlite
dotnet ef migrations add <Nombre> --project src/Arcanist.Core --context PostgresArcanistDbContext --output-dir Data/Migrations/Postgres
```

El proveedor se configura en `Arcanist:Database` (`Provider`: `Sqlite`/`Postgres`, `ConnectionString`). Nada se resuelve contra la BD hasta que esa sección existe. Los servicios obtienen el contexto por DI (`ArcanistDbContext`, scoped) o con `IArcanistDbContextFactory`, que es lo que usan los trabajos en segundo plano.

**Distribución** (todas las variantes incluyen el panel y escuchan en el puerto 8484, definido en `appsettings.json`):
- **Paquete para Ubuntu 24.04+ y Debian 12+** (pedido por el usuario): `packaging/linux/deb.sh` hace `arcanist_<versión>-1_<amd64|arm64>.deb` (versión con `~` para las pre-releases) desde el tarball autocontenido: servidor en `/opt/arcanist`, la unidad de siempre en `/usr/lib/systemd/system`, dependencias con alternativas por versión (`libssl3t64 | libssl3`, `libicu78 | … | libicu72`), recomienda ffmpeg y ALSA; al instalar arranca y habilita el servicio, al actualizar lo reinicia, al desinstalar lo para, y nunca borra `/var/lib/arcanist` (ni al purgar). `DEB_MAINTAINER` fija el mantenedor (por defecto la página de issues). La release adjunta los `.deb`. `pwsh packaging/linux/build.ps1` lo construye todo solo con Docker. Probado con `apt install` en contenedores limpios de Ubuntu 24.04 y Debian 12 (dependencias y arranque).
- **macOS** (pedido por el usuario; `packaging/macos/`, ver su README; decidido con él: la app arranca al iniciar sesión, tap propio de Homebrew y Portfile en cada release): **Arcanist.app** es `src/Arcanist.Tray` compilada para `net10.0` (`osx-arm64`/`osx-x64`): vive en la barra de menús (`MacOSPlatformOptions.ShowInDock = false`), ejecuta el servidor de `Contents/MacOS/server`, se abre al iniciar sesión con un LaunchAgent (`~/Library/LaunchAgents/net.linkfast.arcanist.plist`, `AutoStart`) y se actualiza con Velopack (canales `osx-<arch>`, `edge-osx-<arch>`); el modo servicio es solo de Windows. Datos en `~/Library/Application Support/Arcanist`. `packaging/macos/pack.sh <versión> <arch>` (en un Mac): nativas con `build.sh osx-<arch>`, servidor y app, `.icns` del PNG de 256 px, `vpk pack --noInst` (actualizaciones y el bundle), y del bundle **firmado ad hoc** (cada Mach-O y luego el bundle: Velopack no firma sin identidad y sin firma macOS lo da por dañado) el `.dmg` (con el enlace a Applications; portable), el `.pkg` (`pkgbuild`, a /Applications, no reubicable, y lo abre) y el `.zip`, además del servidor solo en `.tar.gz`. `portfile.sh` escribe el port de MacPorts (`arcanist-macports-<versión>.tar.gz`, `aqua/arcanist/Portfile`, versión sin guion). **Homebrew:** cask en `github.com/linkfast/homebrew-arcanist`, que su propio workflow actualiza con cada release. Sin notarizar (decisión abierta, como Authenticode): Gatekeeper pide «Abrir igualmente» la primera vez. **Sin probar en un Mac real.**
- **Pasos comunes de empaquetado** (`packaging/build-steps.ps1`, que usan `synology/build.ps1` y `linux/build.ps1`): nativas, panel, Webamp local y servidor, cada uno en un contenedor, con cachés en volúmenes `arcanist-*`.
- **`edge`** (`.github/workflows/edge.yml`, pedido por el usuario para pruebas): cada cambio en `main` publica `ghcr.io/linkfast/arcanist:edge` y `:edge-<commit>` (amd64 y arm64; a mano se publica otra etiqueta) y **la pre-release `edge` de GitHub** (pedido por el usuario), que se reemplaza en cada build cuando todos los paquetes están listos: instaladores de Windows x64 y arm64, `.deb`, `.spk` de Synology y tarballs, con versión `<versión>-edge.<run>`. Los instaladores edge usan sus propios canales de Velopack (`edge`, `edge-arm64`): nunca se mezclan con las releases (el aviso de versión del servidor ignora la etiqueta `edge`, que no es una versión).
- **Paquetes de una versión** (`.github/workflows/packages.yml`, reutilizable; lo llaman `release.yml` y `edge.yml`, que adjuntan los artefactos al final): panel, Windows x64 y arm64 (`pack.ps1 -Runtime win-arm64`: las nativas se compilan en cruzado con `packaging/native/build.sh win-arm64`, MSVC ARM64 y LLVM del runner; canales `win` —el de las primeras releases— y `win-arm64`), Linux (tarballs y `.deb`) y Synology (`build-local.sh` con `VERSION` y `SPK_REV` = número de commits, que siempre crece: DSM compara versiones sin sufijo). `pwsh packaging/docker/build.ps1` construye la imagen local (`-Up -MusicDir` la levanta con Compose, `-Push -Tag` la publica, `-LocalWebamp` mete el Webamp del clon por el contexto `players` del Dockerfile). Los Compose aceptan `ARCANIST_IMAGE`. El paquete de GHCR nace privado: hay que hacerlo público una vez en sus ajustes.
- **Docker Compose** (`packaging/docker/`, con su README): `compose.yaml` (SQLite en el volumen de datos) y `compose.postgres.yaml` (PostgreSQL 17 al lado, la BD por variables de entorno, así que el asistente no la pregunta y el panel no la migra), con `.env.example` (`MUSIC_DIR`, `ARCANIST_PORT`, `ARCANIST_TAG`, `TZ`, `POSTGRES_PASSWORD`) y líneas comentadas para carpeta de entrada, copias, `/dev/snd` y `network_mode: host` (DLNA). Usan la etiqueta `preview` de la imagen, que el workflow de release pone a la última versión publicada, pre-releases incluidas (`latest`, solo las estables). Probados con la imagen construida en local (ambos completan el setup).
- `docker build -t arcanist .`: imagen multi-etapa. El panel y el servidor se compilan en `$BUILDPLATFORM` y la etapa final no tiene `RUN`, así que `docker buildx build --platform linux/amd64,linux/arm64 .` no necesita QEMU. Usa el usuario `app` y el volumen `/data`; `--build-arg VERSION=x.y.z` fija la versión. Desde el host las peticiones no son loopback, así que el asistente pide el código de setup que aparece en `docker logs`.
- `packaging/linux/pack.sh [versión] [--skip-panel]`: tarballs self-contained linux-x64/arm64 en `artifacts/linux/`, con `arcanist.service` (systemd con `DynamicUser`, `StateDirectory` y `Type=notify`). Probado bajo systemd real en un contenedor.
- `pwsh packaging/windows/pack.ps1 [-Version x.y.z] [-SkipPanel] [-Runtime win-x64|win-arm64] [-Channel <canal>]`: instalador Velopack en `artifacts/windows/releases/`, con el tray como `mainExe` y el servidor en `server\`. vpk se niega a empaquetar una versión igual o menor que otra que ya esté en esa carpeta: borrarla para repetir.
- `packaging/build-panel.sh` compila el panel una vez para todos los paquetes (usa mise si existe). Se quitan los `.pdb`: los nativos de SkiaSharp duplicarían el tamaño.
- `packaging/linux/pack.sh` genera también `…-linux-<arch>-dotnet.tar.gz` (dependientes del runtime de ASP.NET Core 10, unos 70 MB menos), que usa el paquete de Synology.

El asistente de instalación pregunta la carpeta de música, el puerto y muestra el código. **`pwsh packaging/synology/build.ps1 [-Arch x64|arm64|all]`** (pedido por el usuario) genera el `.spk` de prueba con Docker como único requisito: nativas en la imagen `arcanist-native-builder` (`packaging/native/builder.Dockerfile`), panel en `node:24.15.0`, servidor en el SDK de .NET (`pack.sh` con `ARCHES`, `FLAVORS` y `ARTIFACTS_PATH`) y spksrc; cachés en volúmenes `arcanist-*` (así no toca los `node_modules`/`obj` de Windows) y la siguiente revisión automática; **`-LocalWebamp`** (pedido por el usuario) mete el Webamp del clon (`../ArcanistWebPlayers/webamp` o `-WebampPath`) en lugar de la release fijada, construido con su `packages/arcanist-webamp/scripts/pack.ps1` (Docker, o `-Local` con el Node de la máquina; genera el zip reproducible con su SHA-256) y pasado a `pack.sh` como `BUNDLED_PLAYERS_DIRECTORY`. `build-local.sh` hace solo el último paso desde una shell. Probados el CGI y el supervisor en un contenedor que simula DSM; **sin probar en un DSM real** (lo prueba el usuario).

## Qué es Arcanist

Servidor de música self-hosted y open source: un "Spotify personal/familiar". **Es un producto open source de LinkFast (LinkFast S.A.)**: así figura en los metadatos (`Directory.Build.props`, instalador, `package.json`, imagen Docker), el README, "Acerca de" del panel, la página provisional y el fabricante del DLNA. El copyright es "LinkFast S.A. and Arcanist contributors" (el código aportado es de sus autores: DCO sin CLA). El usuario crea bibliotecas a partir de sus carpetas y las consume desde todos sus dispositivos. Compite con [mStream](https://github.com/IrosTheBeggar/mStream) y quiere superarlo.

- **Siempre self-hosted:** Windows (instalador, servicio y tray), Linux, Docker y NAS (Synology primero). **No existe un Arcanist en la nube.**
- **Ultimate Cloud** es un servicio comercial aparte que hace de "Arcanist en la nube" y es compatible con él. Los clientes Ultimate (Ultimate Web Player, Ultimate Desktop y los futuros móviles) hablan con ambos, así que **el contrato de API debe mantenerse estable y versionado**.
- **Integración con Ultimate Cloud:**
  - Una cuenta gratuita vinculada permite usar lo almacenado en Ultimate Cloud como fuente de biblioteca.
  - Un tier de pago añade sincronización con Ultimate Cloud, nubes de terceros (S3) y conexión iroh transparente.
  - Todo lo local es gratis, incluida la red P2P.
- **UI first:** todo se configura desde la web, con un asistente inicial y el panel. La configuración por archivo o variables de entorno es para usuarios avanzados y Docker. La CLI va al final.
- **Archivos tal como vienen:** Arcanist no deduplica bytes ni reescribe archivos para ahorrar espacio. Sí evita **pistas duplicadas en el catálogo**.

## Arquitectura decidida (en implementación)

- **Mapa de rutas (un solo puerto).** No crear rutas fuera de este esquema:
  - `/graphql`: la API principal (HTTP y WebSocket). `/graphql/ui` (GraphiQL) y `/graphql/schema.graphql` (SDL).
  - `/rest/v1/**`: la API OpenAPI, equivalente a GraphQL salvo las suscripciones. Contrato en `/rest/v1/openapi.json` y documentación Scalar en `/rest/docs`.
  - `/admin/**`: este panel, compilado con `--base-href /admin/`.
  - `/health`.
  - `/`: el frontend de reproducción predeterminado (Ultimate Web Player, o uno instalado desde el admin).
  - `/players/{id}/**`: todos los frontends (también el predeterminado).
  - `/ext/{id}/**`: extensiones.
  - **Prefijos que pueden reclamar las extensiones** (`ExtensionHost.ClaimablePrefixes`):
    - La de mStream: `/api/**`, `/media/**`, `/album-art/**` y `/transcode/**`. `/shared/**` queda reservado (enlaces compartidos de mStream, sin implementar).
    - La de Subsonic: `/rest/{método}[.view]`, nunca `/rest/v1`.
  - La extensión DLNA vive en `/ext/dlna/**` (descripción, control SOAP, eventos, audio y carátulas).
- **Una lógica, dos APIs (implementado):**
  - Los resolvers GraphQL (`Api/GraphQL/`) y los endpoints Minimal API (`Api/Rest/`) son capas finas sobre los servicios de `Application/`.
  - La autorización vive **solo** en esos servicios: cada operación empieza con `AccessGuard` (`Authenticated()`, `Permission(...)`, `Admin()`, `RecentAuthentication()`), y lo mismo aplicará al filtrado por biblioteca.
  - Los fallos esperados se lanzan como `ArcanistException` (`Application/Errors.cs`). REST los convierte en problem details con `code`; GraphQL, en errores con `extensions.code` (y `extensions.errors` para validación).
  - **GraphQL usa GraphQL.NET** (MIT) con esquema "type-first": clases parciales `Query` y `Mutation` con métodos **estáticos**, `[Name("campo")]`, `[Description]`, `[Id]` para los Guid y `[FromServices]` para los servicios. Cada funcionalidad añade sus operaciones en su propio archivo parcial.
  - **Hot Chocolate quedó descartado:** todas sus versiones cargan en tiempo de ejecución el IDE Nitro (ChilliCream License 1.0, incompatible con AGPL). No reintroducirlo.
  - **Convención de nombres:** el `operationId` REST (`.WithName(...)`) es el campo GraphQL en PascalCase (`createUser` ↔ `CreateUser`). `ApiContractTests` falla si una operación GraphQL no tiene su equivalente REST. Login y setup existen solo en REST.
  - Los enums se serializan en UPPER_SNAKE_CASE en ambas APIs (`MANAGE_USERS`). GraphQL.NET separaría los dígitos (`MP_3`); `RestEnumNamesAttribute` (atributo global en `GraphQLSetup`) usa la misma conversión que System.Text.Json, así que ambas dicen `MP3`. Los tipos de contrato no se llaman igual que las entidades (`UserAccount`, no `User`).
  - Contratos versionados en `docs/api/schema.graphql` y `docs/api/openapi.json`. `ApiContractTests` falla si difieren de lo que sirve el servidor. Tras un cambio intencionado de API, regenerarlos y revisar el diff:

    ```bash
    ARCANIST_UPDATE_CONTRACTS=1 dotnet test --project tests/Arcanist.Core.Tests -- --filter-class "*ApiContractTests"
    ```

  - **Suscripciones** por WebSocket en `/graphql` (subprotocolos `graphql-transport-ws` y `graphql-ws`). El token va en el payload de `connection_init` como `{"Authorization": "Bearer …"}` y lo valida `WebSocketAuthentication` con `SessionValidator`, igual que en HTTP. Se comprueba al conectar; una suscripción abierta no caduca con el token. Las suscripciones no tienen equivalente REST.
  - Herramientas: GraphiQL en `/graphql/ui` (cargado de jsDelivr con SRI), SDL en `/graphql/schema.graphql`, Scalar en `/rest/docs` (embebido, funciona sin internet).
- **Datos:** EF Core 10 con dos contextos, `SqliteArcanistDbContext` y `PostgresArcanistDbContext`, que heredan de `ArcanistDbContext`.
  - Cada contexto tiene sus migraciones en `Data/Migrations/{Sqlite,Postgres}`. Toda migración se genera **para ambos**.
  - Para la primera release (0.1.0-alpha.1) las migraciones se fusionaron en una `Initial` por proveedor, con el ID de la última que había (`20261018103204_UploadSource` en SQLite, `20261018103224_UploadSource` en PostgreSQL): un servidor que ya las tenía todas la da por aplicada. **Ya está publicada: nunca reescribir ni fusionar migraciones.** Evitar operaciones que en SQLite obligan a reconstruir la tabla (renombrar o borrar columnas) salvo que sea imprescindible.
  - Claves `Guid.CreateVersion7()`, fechas como `DateTime` UTC, sin SQL específico de un proveedor. **Excepciones: la búsqueda** (`Data/Search/FullTextSearch.cs`), ver "Búsqueda", y la versión y el tamaño de la propia base de datos en `StorageUsageService`.
  - El usuario elige SQLite o PostgreSQL en el asistente.
  - **Nunca** colocar el `.db` de SQLite en SMB/NFS.
- **Catálogo:**
  - `MediaFile` es el archivo físico, con `ContentHash` calculado solo sobre el audio.
  - `Track` es una grabación dentro de un álbum y puede tener varios `MediaFile`.
  - `Recording` es la grabación lógica, identificada por MBID o AcoustID.
  - Los datos de usuario cuelgan de `Track`/`Recording`, nunca de rutas.
  - La deduplicación va por `ContentHash`/MBID y, más adelante, por Chromaprint/AcoustID.
- **Almacenamiento (implementado):** `Library` → varias `LibrarySource`, siempre leídas a través de `ILibraryStorage` (`Storage/`), que se obtiene por tipo con `ILibraryStorageResolver`.
  - Nunca usar `System.IO` sobre archivos de bibliotecas fuera de `LocalStorage`. La única excepción es `DirectoryBrowser`, que lista y crea carpetas del servidor para elegir ubicaciones.
  - `LocalStorage` ignora archivos y carpetas ocultos (`.`) y carpetas de sistema de NAS y SO (`@eaDir`, `#recycle`, `$RECYCLE.BIN`…). También rechaza rutas relativas que escapen de la raíz.
  - **Las rutas relativas se guardan tal cual están en disco, sin normalizar Unicode:** en Linux, un nombre en NFD (copiado desde un Mac) solo se abre con esa grafía exacta.
  - Las ubicaciones se validan con `LibraryRules` (compartido con el setup): deben existir y ser legibles, y no pueden repetirse ni anidarse dentro de la misma biblioteca (código `overlapping`). Entre bibliotecas distintas sí pueden coincidir.
  - **Una carpeta por biblioteca local** (`too_many` al crear, en el setup y al añadir). **No se puede quitar** (`last_source`, decidido con el usuario): se mueve. Las creadas antes con varias las conservan y pueden quitar las demás.
  - **Mover la carpeta** (`LibraryMoves`, `moveLibrarySource`/`librarySourceMoves`, admin con step-up; botón en cada carpeta local del panel): con el candado de la biblioteca, copia todos los archivos (también ocultos y la papelera; no los `.arcanist-partial-*`) a la carpeta nueva con su fecha de modificación (`LocalStorage.CopyFileAsync`, nombre oculto y renombrado), comprueba los tamaños, cambia `LibrarySource.Location` (las rutas son relativas: el catálogo no cambia) y, salvo `keepOriginals`, borra los originales y las carpetas que quedan vacías (nunca la raíz). Nunca sobrescribe: un archivo igual (mismo tamaño) ya en el destino cuenta como copiado (reanudar), uno distinto detiene el traslado antes de cambiar nada (`storage_conflict`). En memoria: un reinicio a mitad deja la biblioteca en la carpeta anterior. Tests: `LibraryMoveTests`.
  - **Escrituras (F4):** `MoveAsync`, `ImportAsync` (trae un archivo local; entra con un nombre oculto `.arcanist-partial-*` y se renombra, así nunca se ve a medias), `TrashAsync`, `PurgeTrashAsync`, `RemoveEmptyFoldersAsync`, `CanWriteAsync` y `Watch` (FileSystemWatcher; null si no se puede vigilar). **Nunca sobrescriben** (`StorageConflictException`) **ni borran**: lo que se quita va a `.arcanist-trash/<aaaa-mm-dd>/` en la raíz de la ubicación (oculta, así que los escaneos no la ven) y se purga a los `Arcanist:Organization:TrashRetentionDays` (30).
- **Bibliotecas (implementado):** `Application/Libraries/`.
  - Cada usuario ve las bibliotecas concedidas más las `VisibleToAll`; las demás responden 404, para no revelar que existen.
  - `sources` (las rutas) solo se devuelve a quien tiene `MANAGE_LIBRARIES`.
  - Un gestor que no es admin solo gestiona las bibliotecas que ve, y recibe acceso automático a las que crea.
  - Borrar una biblioteca exige step-up y **nunca toca los archivos**.
  - `serverDirectories` y `createServerDirectory` son solo para admins; durante el setup, `GET`/`POST /rest/v1/setup/directories`. Los nombres de carpeta nuevos se validan con las reglas de Windows, las más estrictas.
- **Escáner (implementado):** `Scanning/` y `Application/Scanning/`.
  - `ScanCoordinator` encola trabajos (`ScanJob` en BD) y `ScanWorker` (BackgroundService) los ejecuta **de uno en uno**. Una biblioteca nunca tiene dos trabajos activos. Al arrancar se recuperan los encolados y los interrumpidos.
  - Se escanea automáticamente al completar el setup, al crear una biblioteca y al añadir o quitar fuentes.
  - `LibraryScanner` procesa cada fuente así:
    1. Lista los archivos a través de `ILibraryStorage`.
    2. Salta los que no cambiaron en tamaño ni mtime (±2 s); los escaneos `Full` releen todo.
    3. Lee en paralelo (`Arcanist:Scanner:Parallelism`) con ATL (`TagReader`), calcula el `ContentHash` (`ContentHasher`, solo del audio) y guarda las carátulas (`ArtworkStore`, deduplicadas por SHA-256 en `<datos>/cache/artwork/`).

  - **Importar en el asistente** (decidido con el usuario; también al ejecutarlo de nuevo, tras la bienvenida): otro Arcanist, mStream o un servidor DLNA, como tarjetas fijas (el tamaño de la tarjeta del asistente no cambia) que abren cada una su diálogo y se pueden reabrir (pedido por el usuario); se elige una. **Todas bloquean** (pedido por el usuario): van en `SetupRequest` (`Arcanist`, `Mstream`, `Dlna`; sus bibliotecas son carpetas de las del asistente, que las añade al paso de bibliotecas con su origen) y se registran en la misma transacción; el ajuste `setup.migration` guarda `["arcanist:<id>", "dlna:<id>", "mstream:<id>"]` (o el Guid de mStream de antes), `GET /rest/v1/setup/status` dice `migrating` mientras alguna siga, y el panel (`migrationGuard`) vuelve a la pantalla de progreso del asistente hasta que terminen, aunque se recargue. Antes de haber cuenta se leen con `/rest/v1/setup/{arcanist,dlna,mstream}/…`. Al ejecutarlo de nuevo usan la API del panel, empiezan al final y se puede salir: el asistente lleva a Importación.
  - **Al recargar no se pierde lo avanzado** (pedido por el usuario): las respuestas y el paso se guardan en `sessionStorage` (`arcanist.setupDraft`, en `pagehide` y en cada cambio de paso), nunca las contraseñas ni la conexión de PostgreSQL: al terminar, si faltan, el asistente vuelve al paso que las pide. **Selector de pasos abajo** (pedido por el usuario): hacia atrás va directo; hacia delante valida los pasos intermedios y se para en el primero que necesite algo.
  - **Migrar desde otro servidor** (paso "¿Vienes de otro servidor?"): `POST /rest/v1/setup/mstream/analyze` lee la instalación; las bibliotecas elegidas pasan al paso de bibliotecas y `SetupRequest.Mstream` dice a qué carpeta va cada vpath. La importación (usuarios incluidos; si uno se llama como el admin, sus datos van al admin) se guarda en la misma transacción. Tras completar, el asistente inicia sesión y muestra el progreso de los primeros escaneos y de la importación (`scanJobs`, `mstreamImports`) hasta que el usuario va al panel.
  - **Paso Ultimate** (pedido por el usuario; `features/setup/setup-ultimate.ts`, antes de Extensiones, también al ejecutar el asistente de nuevo): presenta Ultimate Desktop y Ultimate Cloud (esta solo si los servicios externos no están en `NONE`) y las mejoras de IA y Ultimate (`ai`, **activada por defecto**, y `server-audio`). Las **estadísticas anónimas** (rankings de Ultimate) vienen activadas salvo que la privacidad lo impida.
  - **Usuarios, red P2P y extensiones/reproductores** (pasos del asistente, saltables, decididos con el usuario; `features/setup/setup-extras.ts` y `setup-steps.ts`): no van en `SetupRequest`. Al terminar (y al terminar el asistente de nuevo), el panel los aplica con la sesión del admin y las mismas operaciones del panel (`createUser`, `setP2pSettings`, `setExtensionEnabled`, `installExtensionFromUrl`, `installFrontendFromUrl`/`setDefaultFrontend`); lo que falla se muestra sin deshacer el resto. La P2P empieza apagada.
  - **Términos y descargo de responsabilidad** (pedido por el usuario; `Legal/terms.json` incrustado y `Legal/LegalTerms.cs`, guía en `docs/legal/README.md`; **borrador pendiente de revisión legal**): paso «Términos» del asistente tras la bienvenida, que no termina sin la versión vigente (`SetupRequest.AcceptedTerms`, `terms_not_accepted`; queda en `legal.acceptance` con quién y cuándo); `legalTerms(language, audience)` / `GET /rest/v1/legal/terms`, anónimo, también antes del setup. Modo `SELF_HOSTED` (tal cual, errores solo como issues de GitHub) o `LINKFAST_SERVICE` mientras corre una extensión del servicio de LinkFast (`LegalService.ServiceExtensions`: `arcanist-cloud-storage`): soporte y garantías de su contrato. Los usuarios (`audience` USER, sin la sección de marca) los aceptan en Webamp la primera vez (en el navegador, por versión). **SaaS solo de LinkFast** (decidido con el usuario): como la AGPL no permite restringirlo, los términos lo reservan por la **marca** (ofrecerlo comercialmente con los nombres Arcanist/LinkFast), sin limitar la licencia del código. Cambiar el texto exige subir su `version`.
  - **Privacidad** (`Application/Server/PrivacyService.cs`, ajuste `privacy.settings`; en el asistente, en `SetupRequest.Privacy` y en Ajustes, tarjeta Privacidad, decidido con el usuario; en el panel, un **semáforo** de tres niveles, `shared/privacy-level.ts`, pedido por el usuario: verde todo activado, ámbar sin telemetría, rojo sin telemetría ni servicios externos (`NONE`); «Ajustar en detalle» muestra las tres casillas para las combinaciones intermedias, que se ven como «Personalizada»; en el asistente, volver a permitir los servicios externos vuelve a encender los servicios en línea): *sin telemetría* (estadísticas anónimas apagadas y sin poder encenderse, `telemetry_disabled`; las cuentas vinculadas pasan a no enviar reproducciones ni álbumes completos, y las nuevas empiezan así) y *servicios externos* `ALL`, `ULTIMATE_CLOUD_ONLY` (servicios en línea apagados: `OnlineSettings` devuelve ninguno y encenderlos es `external_services_disabled`) o `NONE` (además la extensión de Ultimate Cloud se apaga y no se puede encender). Relajarla no vuelve a encender nada. No afecta a DLNA, Subsonic, mStream ni la P2P.
  - **ffmpeg en el asistente** (pedido por el usuario): si no lo encuentra y hay build para la máquina, el paso Audio ofrece descargarlo (`POST /rest/v1/setup/ffmpeg/install`, con el código; `GET` de lo mismo da el progreso fuera del rate limit, porque no dice nada) con el mismo `FfmpegDownloader` que Ajustes, a `<datos>/tools/ffmpeg`, donde el localizador lo encuentra solo. Al ejecutar el asistente de nuevo usa `installFfmpeg`.
  - Desde fuera de loopback (o a través de un proxy) se exige la cabecera `X-Setup-Code`.
  - `ISettingsFileWriter` escribe `arcanist.json` y recarga la configuración en el acto.
- **Autenticación (implementada):** `Auth/` y `Api/Rest/AuthEndpoints.cs`.
  - `POST /rest/v1/auth/{login,refresh,logout,reauthenticate}`.
  - JWT HS256 de 15 min, firmado con la clave de `<datos>/keys/`. Claims: `sub`, `sid` (sesión), `sstamp`, `auth_time`.
  - Token de refresco opaco y rotatorio, guardado como hash en `UserSession`; la rotación es atómica (`ExecuteUpdate` condicionado al hash anterior). Con `useCookie` va en la cookie HttpOnly `arcanist_refresh`, limitada a `/rest/v1/auth`.
  - Cada petición valida usuario, `SecurityStamp` y sesión contra `UserAccessCache` (30 s). **Al cambiar permisos, acceso a bibliotecas, contraseña o estado de un usuario, llamar a `UserAccessCache.InvalidateUser/InvalidateSession/InvalidateAll`.**
  - El usuario actual se obtiene con `ICurrentUser.Access` (`UserAccess`: `Has(permiso)`, `CanAccessLibrary(id)`).
  - Políticas en `Auth/Policies`: `Policies.Permission(Permissions.X)`, `Policies.Admin` y `Policies.RecentAuthentication`. Esta última es el step-up y falla con 403 `reauthentication_required`.
  - Protección del login: rate limit `auth` por IP (también en el setup) y bloqueo exponencial por cuenta en `LoginThrottle`.
  - `TimeProvider` inyectado en todo lo que depende de la hora; los tests usan `FakeTimeProvider` a través de `new ArcanistFactory(time: …)`.
- **Errores de API como códigos:** `Api/Problems.cs`. REST devuelve problem details con `code`, y los errores de validación son `{ campo: [código] }`. La UI traduce los códigos; no mostrar textos del servidor.
- **Seguridad:**
  - Se asume que el puerto puede estar abierto a internet: rate limiting en auth y setup, y `ForwardedHeaders` para proxies inversos. Se confía en loopback más lo que se liste en `Arcanist:Network:TrustedProxies`.
  - El código de setup se exige fuera de loopback.
  - Los frontends y extensiones de terceros tienen confianza total: se avisa al instalarlos y se pide reautenticación para las acciones sensibles.

- **Windows (implementado):** `src/Arcanist.Tray`.
  - Velopack instala por usuario en `%LocalAppData%\Arcanist`, sin elevación. El tray arranca con Windows (clave `Run` de HKCU) y ejecuta el servidor de `current\server\` como proceso hijo. Si se cae, lo reinicia con espera creciente; tras 3 caídas seguidas se rinde.
  - Actualiza desde GitHub Releases (`UpdateManager` + `GithubSource`). Antes de aplicar una actualización detiene el servidor. Una pre-release instalada se actualiza también a pre-releases; una estable, solo a estables (`Updater.FollowsPrereleases`).
  - Los datos están en `%ProgramData%\Arcanist`, compartidos por los dos modos.
  - **Modo servicio opcional:** `ServiceHelper` se ejecuta elevado (`Arcanist.Tray.exe --service-helper install|update|uninstall|start|stop`) y deja un registro en `logs/service-helper.log`. Al instalar:
    - copia el servidor a `%ProgramFiles%\Arcanist\server`, nunca a una carpeta que el usuario pueda modificar;
    - lo registra con `sc.exe` como `NT SERVICE\Arcanist` (cuenta virtual) con arranque retrasado y reinicio ante fallos;
    - da permiso de escritura en los datos y de lectura en las carpetas de música elegidas;
    - deja al usuario iniciar y detener el servicio sin elevación (ACE en el SDDL);
    - abre el puerto en el firewall solo para redes privadas y de dominio.
  - El tray detecta el servicio y lo controla. Tras una actualización aplicada en modo servicio, se reinicia con `--update-service` y actualiza también el servicio (con UAC).
  - Para música en un NAS se recomienda el modo app o cambiar la cuenta del servicio en `services.msc`.
- **Synology:** DSM 7.2+, x64 y ARMv8. Usa `SERVICE_USER=auto` (`sc-arcanist`), los datos van en `SYNOPKG_PKGVAR` y la carpeta compartida de música sale del asistente (`SERVICE_WIZARD_SHARENAME`). El asistente genera y muestra el código de setup, que `service_postinst` escribe en `setup-code.txt`.

Decididas en la F3:
- **Análisis de audio en una crate Rust** (`native/arcanist-audio`): Symphonia (MPL-2.0) decodifica; `ebur128`, `rusty-chromaprint` y `rustfft` calculan loudness, huella y BPM/tonalidad. Decididas en la F4 (sin consultar, por ser las opciones conservadoras; revisables):
- **Organizar nunca es automático sobre lo que ya existe:** activar la organización automática solo afecta a lo añadido después; el resto requiere "Organizar ahora" tras la vista previa, con step-up y registro para deshacer.
- **Nada se borra:** lo que sustituye `KeepBest`, los originales convertidos y lo descartado van a la papelera de su ubicación durante 30 días.
- **Las etiquetas solo se escriben en archivos que se están importando, antes de entrar en la biblioteca:** cuando un admin las completa en la cola de revisión, y (decidido con el usuario tras la importación DLNA) los campos que le faltan a una copia descargada de un servidor DLNA, con su descripción. Los archivos de las bibliotecas solo se re-etiquetan cuando un usuario edita una pista o su carátula desde la API (pedido por el usuario para Ultimate Desktop; el original queda en la papelera).
- La política de duplicados por defecto es omitir.
